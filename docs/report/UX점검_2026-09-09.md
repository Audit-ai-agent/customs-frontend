## 0. 새 케이스로 재검증 (E0002, 2026-09-09 새 심사 실행)

기존 "테스트케이스"는 8/26 실행 결과라 지난 UI 개선(규칙 한글 제목·판단 사유 프리셋)이 반영되지 않은 데이터였다. 그래서 합성 데이터셋 `error_sets/set_0002`의 PDF 4종(INV·PL·BL·CO)으로 Case를 새로 만들고(참조번호 E0002), 업로드 → 추출 검수·확정 → AI 심사(gpt-5.6-luna, 57초)를 실제로 돌려 확인 사항 10건을 받았다. 캡처 50·51·60·61번.

새 데이터에서 확인된 것:
- 반영됨: 판단 사유 select에 사전 정의 7종 + 기타, 심각도 배지 없음, 비교 상세 눈썹에 규칙 한글 제목("Invoice·Packing List 수량·단위 비교 · 불일치", "필수 기재 항목 누락 · 검토 필요"), 상단 완료 배너와 단계 바의 미판단 배지(10).
- 그대로인 것: 카드 제목은 여전히 전부 "문서 정합성 확인 사항"(규칙 제목은 눈썹으로만), 기준값에 `packing_no`·`hs_code`·`shipping_marks` 원시 필드명, "이어서 할 일" 10줄 반복, 판단 폼 기본값 미리 선택, 카드 10개 전부 빨간 테두리. 페이지 높이 8,308px.
- 새로 발견: 교차 검증 표 "검사" 열이 원시 규칙 코드(`required_field_presence`, `hs_code_presence`)로 표시됨. B/L 번호·컨테이너 번호·총중량 비교의 규칙 제목이 "담당자 확인 사항"으로 떨어짐(`RULE_TITLES`에 해당 코드 없음). 문장 조사 오류 "포장명세서 번호**을**", "HS 코드**을**"(을/를 처리 없음). 확정된 문서에도 "스캔·이미지 OCR 실행" 비활성 상자가 남아 있음.

아래 H1~H5는 새 데이터 기준으로 다시 확인한 뒤 유지·구체화한 항목이다.

## 1. 우선순위 높음 (업무 오류·피로와 직결)

### H1. 판단 기록 폼의 기본값이 "확인함 · 원본 서류 대조 결과 이상 없음"으로 미리 선택되어 있다
- 위치: 통관 심사 단계, 확인 사항 카드 12개 전부 (40-review-y900~5400)
- 원칙: 오류 예방(Nielsen #5), 안전한 기본값
- 문제: 내용을 읽지 않고 "판단 기록"만 눌러도 긍정 판정이 저장된다. 12건을 빠르게 넘기려는 담당자가 실수로 승인성 판단을 남길 위험이 가장 크다.
- 개선: 두 select의 기본값을 "선택하십시오"로 두고, 둘 다 선택되기 전에는 "판단 기록" 버튼을 비활성화. 상태 "확인함"을 고를 때만 사유 프리셋을 노출.

### H2. 통관 심사 화면이 12,455px로 지나치게 길고 같은 폼이 12번 반복된다
- 위치: 통관 심사 단계 전체
- 원칙: 힉의 법칙, 점진적 공개, 인식 부하
- 문제: 확인 사항 12건마다 판단 상태·사유·추가 의견·정정 제안 폼이 모두 펼쳐져 있다. 스크롤 12화면 분량이라 "몇 건 남았는지"를 잃는다. 하단 "이어서 할 일"에도 "확인 사항 판단 · 문서 정합성 확인 사항"이 12줄 그대로 반복된다.
- 개선:
  - 카드 기본 접힘: 제목 한 줄 + 기준/관측 요약 + [판단하기] 버튼. 클릭 시 해당 카드만 펼침.
  - 상단에 고정(sticky) 진행 표시 "판단 12건 중 0건 기록" + 다음 미판단으로 이동 버튼.
  - 같은 규칙의 확인 사항은 그룹 헤더로 묶고(예: "필수 항목 누락 5건"), 그룹 단위 일괄 판단 옵션 제공.
  - "이어서 할 일"은 집계형으로: "문서 정합성 확인 사항 10건 판단 기록", "원문 근거 확인 2건".

### H3. 확인 사항 카드 제목이 전부 "문서 정합성 확인 사항"으로 같다
- 위치: 통관 심사, 심사 기록·운영 지표의 규칙 라벨("담당자 확인 사항" ×7)
- 원칙: 시각 계층, 인식 우선(Nielsen #6)
- 문제: 제목이 정보를 주지 않고, 실제 내용("상업송장과 포장명세서의 수량이 일치하지 않습니다")은 회색 부제로 내려가 있다. 운영 지표의 "확인 사항이 많이 뜨는 규칙" 차트도 라벨 7개가 동일해 비교가 불가능하다.
- 개선(구체): `findingTitle()`이 finding.code로 `RULE_TITLES`를 찾지 못하면 연결된 comparison의 `ruleTitle()`을 제목으로 쓰고, 그것도 없으면 message 첫 문장을 제목으로. `RULE_TITLES`에 B/L 번호·컨테이너 번호·총중량·shipping_marks 규칙 코드 추가. 지표 차트도 같은 함수를 사용.

### H4. 화면 곳곳에 내부 식별자·필드명이 그대로 노출된다
- 위치:
  - 헤더 우측 `7cc8fe39-ac47-4c6f-8411-f9ff84175eb7 · 7 · local-functional승인자, 심사자` (모든 페이지)
  - 심사 업무함·심사 기록의 참조번호 `case_50138c056af24289a14d509821f56df1`
  - 통관 심사의 기준값 `hs_code`, `packing_no`, `shipping_marks`
  - 교차 검증 표 "검사" 열의 규칙 코드 `required_field_presence`, `hs_code_presence`
  - 법령 조회 인용 Case `case_5a11069bcf29…`
- 원칙: 인식 우선, 미니멀(Nielsen #8)
- 문제: 사용자는 세션 UUID나 필드 키를 읽을 수 없다. "7" 배지도 의미가 없다. 헤더의 "local-functional승인자, 심사자"는 계정명과 역할이 붙어 있다.
- 개선: 헤더는 표시 이름 + 역할 칩(심사자·승인자)만, UUID는 툴팁/이용안내로. 참조번호가 없는 Case는 "미지정"으로 표시하고 Case 제목을 첫 열로. 필드 키는 `fieldLabel()`로 한글화(HS 부호, 포장명세서 번호). 인용 Case는 제목으로.

### H5. 빨간색 과다 사용으로 "정상 업무 상태"와 "오류"가 구분되지 않는다
- 위치: 홈·업무함·지표의 "검토 중" 카드(빨강), 통관 심사 카드 12개 전부 빨간 좌측 테두리 + 빨간 "판단 필요" 배지, 심사 기록 판정 열 7행 전부 빨간 "확인 사항 있음"
- 원칙: 폰 레스토르프(하나만 달라야 눈에 띈다), 색 의미 관습
- 문제: 검토 중은 정상적인 진행 상태인데 빨강이어서 문제가 있는 것처럼 읽힌다. 모든 카드가 빨간색이니 어떤 것도 강조되지 않는다.
- 개선: 상태 색을 진행 전=회색, 검토 중=주황/앰버, 종료=초록, 실패/오류만 빨강으로. 카드 테두리는 중립색으로 두고 미판단 카운트와 배지만 색을 준다. 심사 기록 판정은 "확인 12건 / 판단 0건"처럼 숫자로.

## 2. 우선순위 중간 (효율·일관성)

### M1. 홈이 내비게이션을 그대로 반복한다
- 위치: 홈 "바로 가기" 6카드 = 상단 메뉴 6개. 6번째 카드(이용안내)가 홀로 다음 줄에 남아 격자가 깨진다.
- 개선: 홈 상단을 "내가 처리할 검토 중 건 N건" 목록(최근 수정순 5건)과 최근 활동으로 바꾸고, 바로 가기는 제거하거나 3열로 축소. F 패턴상 숫자 카드(심사 현황)를 첫 화면 상단으로.

### M2. 같은 숫자가 세 번 보인다 (업무함)
- 위치: 심사 업무함의 통계 카드 4개 + 필터 칩 4개(전체 7·진행 전 1·검토 중 4·종료 2) + 홈·지표에도 동일 카드
- 개선: 통계 카드를 클릭 가능한 필터로 만들고 칩을 제거. 상태 흐름도·처리 흐름 카드는 업무함 하단에서 빼고 이용안내로 이동(또는 접힘). 7건 목록에 페이지 높이 1,949px은 과하다.

### M3. 헤더 영역이 세로 공간을 많이 차지한다
- 위치: 유틸바(글자크기·로그아웃) + 브랜드바 + 메뉴 + 히어로(제목·설명) = 첫 콘텐츠가 약 330px 아래에서 시작
- 문제: 1366×768 노트북에서는 화면 40% 이상이 헤더. 워크스페이스에서는 여기에 탭·단계 바가 더해진다.
- 개선: 유틸바와 브랜드바를 한 줄로 합치고, 히어로 설명 문장은 페이지 첫 진입에만 또는 제거. 워크스페이스에서는 히어로를 한 줄(제목·상태·활성 문서)로 축소.

### M4. 카드 제목 크기가 페이지마다 다르다
- 위치: "심사에 인용된 법령 근거", "전체 심사 기록", "Case 현황", "현재 설정"은 크게(약 1.5배), 같은 페이지의 "법령 원문 검색", "심사 실행", "설정 변경"은 작게
- 원칙: 시각 계층 일관성, 게슈탈트 유사성
- 개선: `SectionHeading` 한 종류로 통일. 큰 제목은 페이지 히어로에만.

### M5. "항상 사람 검토 필요" 칩이 버튼처럼 보인다
- 위치: 워크스페이스 헤더 우측, "AI 심사 다시 실행" 버튼과 같은 높이·모양
- 원칙: 어포던스(Norman)
- 개선: 상태 배지는 작게, 버튼과 다른 형태(모서리·높이)로. 또는 부제 줄로 이동.

### M6. 새 Case 등록 모달의 주 버튼이 약하고 안내가 없다
- 위치: 30-new-case
- 문제: "새 Case 만들기"가 연한 배경(secondary) 스타일이라 주 행동으로 읽히지 않는다. "업무 참조번호"가 무엇인지(예: 수입신고번호, 사내 관리번호) 설명이 없다.
- 개선: 채워진 primary 버튼으로. 참조번호에 도움말 한 줄과 예시 placeholder. 제목 미입력 시 버튼 비활성.

### M7. 비활성 버튼의 이유가 없다
- 위치: 심사 이력 "선택한 정정으로 재심사"(비활성), 법령 조회 "법령 검색"(비활성)
- 개선: 비활성 옆에 이유 한 줄("승인된 정정 제안을 먼저 선택하십시오", "두 글자 이상 입력") 또는 툴팁.

### M8. 검색 결과에 건수·범위 표시가 없다
- 위치: HSK 검색(10건만 표시, 더 있는지 알 수 없음), 법령 검색(조문 전문이 길게 나열)
- 개선: "결과 N건 중 10건 표시" + 더 보기. 법령 결과는 조문 제목 + 2줄 요약으로 접고 펼치기. 인용 Case는 제목으로 표시.

### M9. 관세 진단의 세율 목록이 접히지 않는다
- 위치: 20-case-duty, "적용 가능 세율 사다리" 약 10행 + "세율 출처" 약 40행에 "출처 열기" 반복
- 개선: 적용 가능(요건 충족)한 세율만 기본 표시, 나머지는 "요건 미충족 N건 보기"로 접기. 출처는 협정 그룹별 접힘.

### M10. 단계 모델이 세 가지다
- 위치: 홈 "처리 절차" 5단계, 워크스페이스 4단계(서류 등록·교차 검증·통관 심사·관세 진단), 이용안내 "담당자 업무 순서" 6단계 + "AI 처리 절차" 5단계
- 원칙: 일관성(Nielsen #4), 야콥의 법칙
- 개선: 사용자에게 보이는 단계는 워크스페이스 4단계 하나로 통일하고, AI 내부 절차는 이용안내에서만 "AI가 내부적으로 수행하는 일"로 구분 표기.

## 3. 우선순위 낮음 (마감)

- L1. 푸터 "KRDS(대한민국 정부 디자인 시스템) 문법을 적용한 업무 화면입니다"는 개발자 문구. 기관명·문의·버전으로 교체.
- L2. 이용안내 "역할과 권한"·"키보드 단축키" 표의 값이 우측 정렬되어 긴 문장이 읽기 어렵다. 좌측 정렬.
- L3. 심사 기록·업무함 표의 열 헤더 정렬 표시(↕, ▼)가 한 열에만 있어 어떤 열이 정렬 가능한지 불분명. 정렬 가능 열 모두에 아이콘.
- L4. AI 도우미 대화 제목 "제목 없는 대화" → 첫 질문 앞 20자로 자동 제목.
- L5. 관리자 설정의 제공자 칩이 점선 테두리라 비활성처럼 보인다. 실선 배지로.
- L6. 문서 등록의 "스캔·이미지 OCR 실행" 상자가 비활성 입력창처럼 보여 버튼인지 알 수 없다. 버튼 형태로.
- L7. 로그인 화면에 문의처가 없다. 계정 문제 시 연락처 한 줄.
- L8-1. 문장 조사 오류: "포장명세서 번호을", "HS 코드을" → 필드명 뒤 을/를을 받침 유무로 선택하거나 "필수 항목(HS 코드)을 확인할 수 없습니다"처럼 괄호 구문으로 우회.
- L8-2. 확정된 문서에도 "스캔·이미지 OCR 실행" 상자가 비활성 상태로 남는다. 확정 후에는 숨기고 "확정됨 · 원문 보기"만.
- L8. 회색 보조 텍스트(설명·placeholder) 대비가 낮아 보이는 곳이 많다. WCAG 4.5:1 기준으로 색 토큰 점검 권장(측정은 미실시).

## 4. 잘 되어 있는 것 (유지)

- 로그인이 자동 리다이렉트가 아니라 명시적 버튼이며, 로그인 후 원래 주소로 돌아온다.
- 본문 건너뛰기 링크, 글자 크기 조절, 브레드크럼, 단축키 안내가 있다.
- 워크스페이스 단계 바에 미판단 건수(12) 배지가 붙어 어디를 봐야 하는지 알려 준다.
- "판단 기록 전에는 종료 불가", "자동 종료 경로 없음" 같은 책임 범위를 화면에서 반복해 알려 준다.
- 관리자 설정: 저장 전 연결 테스트, 되돌리기 확인창, 권한 없는 사용자에게 읽기 전용 안내.
